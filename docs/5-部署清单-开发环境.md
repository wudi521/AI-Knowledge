# 部署清单:开发环境

> 版本:v1.0 · 2026-08-15
> 目标:在一台开发机(Mac, Docker Desktop)上把 AI 客服知识库系统的开发环境完整跑起来。
> 配套文档:《4-技术方案.md》(架构与服务划分)、《3-PRD产品需求文档.md》(功能与验收)
> 交付物:本文档 + `deploy/dev/docker-compose.dev.yml` + `deploy/dev/init-dev.sh`

## 1. 环境拓扑总览

开发环境采用"**单机 Docker 起中间件 + IDE 本地起后端 + 前端本地跑**"的形态,与生产(K8s)隔离,改动即时生效。

```
┌──────────────────────────── 开发机(Mac) ───────────────────────────┐
│  Docker Desktop                                                      │
│  ├─ postgres:16     :5432    业务与知识元数据(PG,向量已迁 Milvus)   │
│  ├─ milvus v2.4     :19530   向量召回(Milvus standalone)             │
│  │    └─ etcd + milvus-minio(内部,不映射端口)                        │
│  ├─ elasticsearch:8 :9200    BM25 全文 + 元数据过滤(单节点,关安全)   │
│  ├─ redis:7         :6379    会话/限流/缓存                          │
│  ├─ kafka 3.7       :9092    KRaft 单节点,异步任务                   │
│  ├─ minio-biz       :9000/9001  业务对象存储(文档/媒体)              │
│  └─ nacos 2.x       :8848   注册中心 + 配置中心(standalone)          │
│                                                                      │
│  IDE(IntelliJ IDEA)起后端微服务:端口 8000 ~ 8111                     │
│  Node 起前端 admin-console:端口 5173                                  │
└──────────────────────────────────────────────────────────────────────┘
```

| 检查项 | 要求 | 说明 |
|--------|------|------|

| 网络 | 可拉取 Docker Hub / 阿里云镜像 | 镜像拉取 |

### 4.2 启动命令

```bash
cd deploy/dev
docker compose -f docker-compose.dev.yml up -d          # 首次会拉镜像,耐心等待
docker compose -f docker-compose.dev.yml ps             # 查看状态(health 列)
docker compose -f docker-compose.dev.yml logs -f milvus # 查看某个服务日志
docker compose -f docker-compose.dev.yml down           # 停止(保留数据)
docker compose -f docker-compose.dev.yml down -v        # 停止并清空数据(重来)
```

### 4.3 健康检查(全部 healthy 再继续)

```bash
# PostgreSQL
docker compose exec postgres pg_isready -U ai_cs -d ai_cs_kb
# Redis
docker compose exec redis redis-cli ping          # 返回 PONG
# Elasticsearch
curl -s http://localhost:9200/_cluster/health     # status 应为 yellow/green
# Kafka
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
# MinIO
curl -s http://localhost:9000/minio/health/live
# Nacos
curl -s http://localhost:8848/nacos/v1/console/health/readiness   # 返回 ok
# Milvus(首次启动较慢,最多等 2~3 分钟)
curl -s http://localhost:9091/healthz              # 返回 {"status":"OK"}
```

## 5. 初始化(一次性)

执行 `deploy/dev/init-dev.sh`,自动完成:等待中间件就绪 → 创建 MinIO 业务桶 `kb-docs` → 创建 Kafka 主题(4 个)→ 输出就绪信息。

```bash
cd deploy/dev
bash init-dev.sh
```

主题与桶清单:

| 资源 | 名称 | 用途 |
|------|------|------|
| MinIO 桶 | kb-docs | 原始文档与媒体文件(路径 `{tenant}/{kb}/{doc}/{version}/`) |
| Kafka 主题 | knowledge-ingest | 文档入库流水线(解析→切分→向量化→索引) |
| Kafka 主题 | chat-events | 会话事件流(追踪/评测/审计) |
| Kafka 主题 | eval-tasks | 评测任务 |
| Kafka 主题 | audit-events | 审计日志 |

说明:ES 的 chunk 索引与 Milvus 的 collection 由应用启动时自动创建(见第 6 节),开发环境无需手动建。ES 中文分词插件(ik)可选:构建 `es-ik` 镜像(附录 A 注释掉的部分),不装则先用默认分词,不影响启动。

## 6. 配置中心 Nacos 与本地服务配置

开发环境使用 Nacos 做注册与配置(服务启动后自动注册)。各服务 `bootstrap.yml` 关键配置(统一指向本机):

```yaml
spring:
  application:
    name: chat-service            # 各服务不同
  cloud:
    nacos:
      server-addr: 127.0.0.1:8848
      discovery:                  # 注册中心
        namespace: dev
      config:                     # 配置中心(可选,也可用本地 application.yml)
        namespace: dev
  datasource:                     # 仅需要连 PG 的服务
    url: jdbc:postgresql://127.0.0.1:5432/ai_cs_kb
    username: ai_cs
    password: ai_cs_dev_2026
  data:
    redis:
      host: 127.0.0.1
      port: 6379
```

### 9.2 冒烟测试(最小闭环)

```bash
# 1. 各服务健康
for p in 8000 8101 8102 8103 8104 8105 8109; do
  curl -s http://localhost:$p/actuator/health | grep -o '"status":"[A-Z]*"'
done

# 2. 上传文档 → 返回 task_id(异步)
curl -s -X POST http://localhost:8000/api/kb/documents \
  -F "file=@/path/to/售后政策.pdf" -F "kbId=KB-001"

# 3. 查询入库任务状态(等 pipeline 完成)
curl -s http://localhost:8000/api/ingest/tasks/{task_id}

# 4. 检索实验室(混合检索 + 证据)
curl -s -X POST http://localhost:8000/api/retrieval/search \
  -H "Content-Type: application/json" \
  -d '{"query":"碎屏能免费修吗?","tenantId":"0182"}'

# 5. 对话(SSE 流式)
curl -N -X POST http://localhost:8000/api/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"conversationId":"demo-001","message":"碎屏能免费修吗?"}'
```

冒烟通过标准:上传返回 task_id;任务状态 10 分钟内变 PUBLISHED;检索返回带证据编号的结果;对话流式返回带 [C1][C2] 引用的答案。

## 10. 常见问题与排查

| 现象 | 原因 | 处理 |
|------|------|------|
| Milvus 一直 unhealthy | standalone 首次启动慢(etcd + 元数据初始化) | 等待 2~3 分钟,`curl localhost:9091/healthz` 手动确认 |
| ES 内存不足退出 | 默认堆过大 | 已在 compose 设 `ES_JAVA_OPTS=-Xms512m -Xmx512m`;若仍 OOM,把 Docker 内存配额调大 |
| Kafka 连接 refused | 容器未就绪或 advertised.listeners 不对 | 等待 healthy;compose 已配 `PLAINTEXT://localhost:9092` 供宿主机访问 |
| 服务注册不上 Nacos | Nacos 未就绪或 namespace 不一致 | `curl localhost:8848/nacos/v1/console/health/readiness`;确认 bootstrap.yml namespace=dev |
| 上传文档后任务一直 PENDING | ingestion-worker 未启动或 Kafka 主题不存在 | 确认 worker 在跑;`kafka-topics.sh --list` 检查 knowledge-ingest |
| 检索中文效果差 | 未装 ik 分词 | 启用附录 A 中 es-ik 构建并重建容器(可选优化) |
| 端口被占用 | 本机已有服务 | 修改 compose 或服务 `server.port`(注意同步前端代理与网关路由) |
| 模型网关 401 | 未配置模型 Key | 在环境变量设置 `MODEL_API_KEY` 等(见第 6 节) |
