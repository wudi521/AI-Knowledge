# 意图管理 / 槽位管理 业务评估文档

> 日期: 2026-08-21 · 状态: 待评审 · 对应需求 5: 用户反馈"不好用", 需业务打磨后决定去留
> 本评估不改代码, 仅梳理功能价值/痛点/场景适配/改进路径/去留建议, 供决策。

---

## 1. 功能价值分析(基于代码事实)

### 1.1 意图管理(ai_intent)

**在管线中的位置**: 检索链路 `SearchService.search` 步骤 3——检索前 `QueryAnalysisService.analyze(query, history, intents)` 把问题分类到知识库意图(LLM + 提示词), 分类结果 `OUT_OF_SCOPE` 时**短路**: 不检索、不硬答、返回"超出该知识库服务范围"并转人工。

**它解决什么问题**:
1. **范围控制**: 客服知识库只回答售后问题, "今天天气怎么样"这类无关问题不应消耗检索/生成, 更不应产生幻觉回答;
2. **可解释性**: 检索测试页能看到"问题被归到哪个意图", 便于运营理解系统行为。

**关键事实**: 意图**不参与召回排序**(BM25/向量/RRF/重排都不消费 intent), 所以对 Recall/MRR/NDCG 等检索指标无直接影响。**不配意图集时, 系统自动回退固定 6 枚举(WARRANTY/REFUND/...)且不拦截**——即"没配意图 ≈ 没有这个功能"。

### 1.2 槽位管理(ai_knowledge_base_slot)

**在管线中的位置**: 证据链路 `EvidenceService.evaluate` 步骤 0——检索前 `SlotDetector` 抽取问题的槽位值(品牌/故障性质/购机时间等), 缺必填槽位 → **反问短路**: 返回 `answerable=false` + `clarifyQuestion`("请补充以下信息: 品牌型号、故障性质"), 不检索, 对话工作台回复反问文案并保持会话 ACTIVE。

**它解决什么问题**:
1. **对话澄清**: "我的手机坏了能免费修吗"没说是哪个品牌/什么故障, 直接检索大概率答非所问; 反问先补齐关键条件;
2. **防答错**: 信息不全时不硬答, 降低错误回答率;
3. 有总开关 `yudao.evidence.slot.enabled`(默认 true), **不配槽位定义 = 检测自动跳过**。

**关键事实**: 槽位检测同样**不参与召回排序**, 对检索指标无直接影响; 影响的是"对话场景的答案质量与澄清体验"。

### 1.3 结论先行

> 两个功能都不是为提高"检索准确率"而存在(那由切分/向量/重排/证据判定负责); 它们服务的是**对话场景的"不硬答"能力**——意图=超范围拦截, 槽位=缺信息反问。去掉对检索指标无影响, 损失的是对话侧的防幻觉与澄清。

## 2. 现状痛点(用户反馈 + 代码佐证)

| 痛点 | 表现 | 代码/事实佐证 |
|---|---|---|
| 配置流程繁琐 | 每个知识库要手动建意图/槽位定义, 入口在知识库行按钮里, 普通业务人员不会配 | IntentController / AiKnowledgeBaseSlotController 均为纯 CRUD, 无模板/引导 |
| 自动生成质量差 | LLM 总结的意图/槽位不准(如"换手机推荐"被宽容归入"常见问题"而非 OUT_OF_SCOPE), 生成后还要人工改 | 交接文档 IT 验证记录: 本地 LLM 判别问题; IntentSummarizer/SlotSummarizer 依赖模型能力 |
| 效果不可见 | 配了之后看不到拦截/反问是否生效, 检索页有意图展示但对话页无反馈闭环 | 对话工作台仅在触发反问时显示文案, 无"本次评估用了哪些意图/槽位"诊断 |
| 业务上没真正用起来 | 功能存在但业务侧没有运营流程支撑(谁维护意图? 多久更新?) | 无运营指标(拦截率/反问率/槽位补齐率)统计 |

## 3. 业务场景适配矩阵

| 业务场景 | 意图管理 | 槽位管理 | 说明 |
|---|---|---|---|
| 客服售后(问题边界清晰, 需追问型号/故障/时间) | **高价值**: 超范围问题拦截转人工 | **高价值**: 缺信息反问 | 两个功能都值得打磨使用 |
| 政策/法规查询(条款明确, 问题开放) | 中: 可只做范围拦截, 不细分意图 | 低: 通常不需要追问 | 意图可留, 槽位可不配 |
| 企业文档检索(知识库内全文检索) | 低: 开放查询, 拦截会误伤 | 低: 无追问场景 | 都不配(自动回退), 功能自动不生效 |
| 专利/技术文档问答 | 低 | 低 | 检索质量靠切分与重排 |

**原则**: 意图/槽位是"对话客服"场景的增强件, 不是检索系统的必需品; **按场景启用, 不必全开**。

## 4. 改进路径建议(若决定保留打磨)

### 4.1 自动生成质量
- 意图总结: 均衡采样(已有 40条/15 优化) + 提示词强制提炼"收费/合同/超范围"类意图; 换更强模型(qwen3-14b 或云端);
- 槽位总结: 增加"常见必填条件"种子模板(品牌/型号/时间/故障), 让 LLM 从模板起步而非白纸;
- 生成结果引入"置信度", 低置信不自动启用, 转"待确认"列表由运营审核。

### 4.2 配置流程
- 意图/槽位提供**模板库**(售后/政策/HR 等预设意图与槽位一键套用);
- 文档上传时按文档类型(FAQ/政策/售后)推荐关联意图集;
- 槽位"从样例问题自动抽取条件"(给 3~5 个样例问题, LLM 提炼必填槽位), 降低配置门槛。

### 4.3 效果可见性
- 运营报表: 拦截率(OUT_OF_SCOPE 占比)/反问率/槽位补齐率/补齐后回答成功率——回答"功能到底有没有用";
- 对话工作台增加"评估诊断"折叠面板: 本次命中的意图、抽取的槽位值、缺失项;
- 意图/槽位变更留审计(已有 mzt-logapi 基建)。

### 4.4 业务运营
- 明确"意图/槽位由谁维护"(建议: 知识库 owner), 纳入知识库上架流程;
- 定义"什么情况该新增意图/槽位"的运营规范。

## 5. 去留决策建议

| 选项 | 适用条件 | 成本 |
|---|---|---|
| **保留但按场景启用(推荐)** | 目标业务含客服对话场景 | 零成本(现状即按需启用); 打磨按需投入 |
| 精简改造(只留 OUT_OF_SCOPE 拦截, 去掉槽位) | 无追问场景, 但需要超范围拦截 | 中: 删槽位链路, 保留意图 |
| 完全移除 | 纯文档检索, 无客服对话 | 高: 删表/服务/管线接入/前端, 后续恢复需重开发 |

**建议**: 先用"按场景启用"跑 1~2 个月, 配合 4.3 的运营指标验证实际价值, 再决定是否投入打磨或移除——避免基于"感觉不好用"做不可逆的删除决策。
