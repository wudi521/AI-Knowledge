# 设计文档:评测平台(考题集 / 评测执行 / 指标 / 上线闸门 / 反馈闭环)

> 日期:2026-08-19 · 状态:待用户确认
> 前置文档:《3-PRD产品需求文档.md》(闭环⑤/BR-018/BR-019/AC-010/AC-011)
> 依赖:检索平台(48086)、证据平台(48087)、对话工作台(48083, 反馈来源)、知识治理(版本发布, 闸门挂载点)
> 范围:eval-server(48092);表 ai_eval_case/ai_eval_task 已建;前端评测页缺失

---

## 1. 背景与目标

系统已能"答"(检索+证据+对话),但缺**质量闭环**:怎么证明答得好?改版(换模型/改Prompt/更新知识库)是变好还是变坏,靠客户投诉才发现。

评测平台把质量变成**可度量的工程流程**:
- 标准考题集(问题+标准答案+期望命中的证据)
- 批量跑链路 → 自动计算指标(Recall/MRR/NDCG/Faithfulness/幻觉率/引用准确率)
- 指标看板 + **上线闸门**(不达标禁止发布新版本)
- 客户负反馈 → 自动生成新考题 → 纳入回归(闭环⑥)

**成功标准**(对齐 BR-018):
- `POST /eval/task/run` 批量评测,输出各指标;`GET /eval/task/page` 看板
- 闸门: 幻觉率≤2% / Faithfulness≥95% / Recall@5≥90% / Citation准确率≥97%, 任一不达标 → 禁止发布(AC-010)
- 反馈→考题: 客户点踩 → 自动生成考题(AC-011)
- 前端评测页: 考题集管理 + 任务列表 + 指标看板 + 失败用例定位

## 2. 架构

```
运营/质检员
  → 考题集管理(ai_eval_case CRUD)
  → 发起评测(EvalTask: suite_id + 全量考题)
eval-server(48092)
  ├─ EvalCaseService      考题集 CRUD + 反馈自动生成
  ├─ EvalRunner           评测执行器(逐题跑链路)
  │     ├─ 调 evidence.evaluate(query, kbIds)   ← 复用完整判定管线(检索+充分性+生成+Claim)
  │     └─ 逐题产出: answerable/answer/claims/citations/evidence 顺序
  ├─ MetricCalculator     指标计算
  │     ├─ Recall@K: gold_chunks ∩ topK results / |gold_chunks|
  │     ├─ MRR/NDCG: gold_chunks 在 results 中的排序质量
  │     ├─ Faithfulness: SUPPORTED claims / 总 claims
  │     ├─ 幻觉率: UNSUPPORTED claims / 总 claims
  │     └─ Citation准确率: 引用 [C1] 指向的 chunk 是否 ∈ gold_chunks
  ├─ EvalReportService    汇总指标 → ai_eval_task.metrics + 逐题结果落库
  └─ PublishGate          闸门判定(供 knowledge 发布时 Feign 调用)
knowledge-server(48084)  发布门禁: publish 前调 eval 闸门(最近一次评测达标才放行)
chat-server(48083)       ai_feedback(点踩) → 自动生成考题(闭环)
```

**关键决策**:
- **评测跑 evidence.evaluate**(非裸检索): 一次调用产出检索顺序+回答+claims+citations,可算全部指标;且验证的是"真实回答链路"而非孤立检索
- **kbIds 参数**: 考题可指定 kbId(该库评测)或空(全部可见)
- **闸门挂 knowledge publish**: publish 方法加门禁 4: 该 kb 最近一次评测全指标达标, 否则 VERSION_PUBLISH_BLOCKED(AC-010);可配置开关(生产默认开)

## 3. 数据模型

**ai_eval_case**(已有, 增列):
- question(必填)/gold_answer(标准答案)/gold_chunks(json: 期望命中的 chunkId 列表)/source_feedback(来源反馈, 闭环用)
- 增量: `kb_id bigint NULL`(指定评测库; 空=全部可见)、`category varchar(32) NULL`(分类: 检索/证据/综合)

**ai_eval_task**(已有):
- suite_id/model/prompt_ver/status(RUNNING→DONE|FAILED)/metrics(json)
- 增量: `kb_id bigint NULL`、`case_count int`、`start_time/end_time datetime`、`gate_pass tinyint`(闸门是否通过)、`fail_cases json`(失败用例明细: caseId+未达标指标, 供定位)

**ai_eval_result**(新表, 逐题结果):
```sql
CREATE TABLE ai_eval_result (
  id bigint PK AUTO_INCREMENT,
  task_id bigint NOT NULL,           -- 评测任务
  case_id bigint NOT NULL,           -- 考题
  answerable tinyint, confidence decimal(5,4),
  recall_at_5 decimal(5,4), mrr decimal(5,4), ndcg decimal(5,4),
  faithfulness decimal(5,4), hallucination_rate decimal(5,4), citation_accuracy decimal(5,4),
  passed tinyint,                    -- 该题是否达标
  fail_reasons varchar(500),         -- 未达标原因
  answer text, trace_id varchar(64), -- 可重放
  + 审计字段
) COMMENT='AI 评测逐题结果';
```

## 4. 指标定义(领域无关, 全部可配置阈值)

| 指标 | 定义 | 阈值(BR-018) | 配置键 |
|---|---|---|---|
| Recall@5 | gold_chunks 命中 top5 的比例 | ≥90% | yudao.eval.gate.recall-at-5 |
| MRR | gold_chunks 首个命中的倒数排名均值 | ≥0.8 | yudao.eval.gate.mrr |
| NDCG@5 | 排序质量(增益衰减) | ≥0.8 | yudao.eval.gate.ndcg |
| Faithfulness | SUPPORTED claims / 总 claims | ≥95% | yudao.eval.gate.faithfulness |
| 幻觉率 | UNSUPPORTED claims / 总 claims | ≤2% | yudao.eval.gate.hallucination |
| Citation准确率 | 引用指向 chunk ∈ gold_chunks 的比例 | ≥97% | yudao.eval.gate.citation-accuracy |
| 闸门开关 | — | 默认开 | yudao.eval.gate.enabled |

## 5. 接口

**考题集**(eval-server):
- `POST /eval/case/create` {question, goldAnswer, goldChunks[], kbId?, category?}
- `PUT /eval/case/update` / `DELETE /eval/case/delete?id=` / `GET /eval/case/page`
- `GET /eval/case/get?id=`
- 权限: eval:case:query/create/update/delete

**评测任务**:
- `POST /eval/task/run` {caseIds? | kbId?, model?} → 创建任务并**异步执行**(逐题跑 evidence, 大任务耗时长); 返回 taskId
- `GET /eval/task/page`(状态/指标摘要/闸门通过)
- `GET /eval/task/get?id=`(metrics + gatePass + failCases)
- `GET /eval/task/result-page?taskId=`(逐题结果)
- 权限: eval:task:run/query

**闸门 RPC**(eval-api, 供 knowledge):
- `EvalApi.checkGate(kbId) → CommonResult<Boolean>`(最近一次该 kb 评测是否全指标达标; 无评测记录 → false 阻断并提示先评测)

**反馈闭环**(chat→eval): chat 侧 ai_feedback 落库后, 异步调 `EvalApi.generateCaseFromFeedback(feedbackId)`:
- 取反馈消息(问题+答案) → 创建考题(question=问题, goldAnswer=null 待人工补, category=综合, sourceFeedback=id)
- 人工在评测页补 gold_answer/gold_chunks 后纳入回归(AC-011)

## 6. 前端评测页

- 菜单: 评测管理(父 2758 AI 大模型), 子菜单 考题集/评测任务(或单页 Tab)
- 考题集页: 表格(问题/答案/标准chunks/kb/分类)+ 新增/编辑/删除/批量导入(JSON)
- 评测任务页: 发起评测(选考题范围/kb)+ 任务列表(状态/各指标/闸门徽标)+ 详情(逐题结果表: 每题指标+失败原因+展开回答/引用)
- 看板: 最近任务指标雷达/条形图(简单展示, 不强求图表库)

## 7. 实施顺序(单计划 7 任务)

1. 接线 + DDL: eval-server pom/RpcConfiguration(EvidenceApi/RetrievalApi/KnowledgeApi)+ ai_eval_result 表 + ai_eval_case/task 增列 + yaml 配置块(阈值/开关)
2. EvalCaseService: 考题 CRUD + 分页 + 反馈生成(api)+ 菜单/权限
3. EvalRunner: 逐题调 evidence.evaluate + 逐题结果落库(异步执行器)
4. MetricCalculator: 指标计算(Recall/MRR/NDCG/Faithfulness/幻觉率/引用准确率)+ 逐题达标判定
5. EvalReportService + Controller: 任务创建/状态/结果查询 + 汇总指标 + gatePass + 权限
6. 闸门挂载: EvalApi.checkGate + knowledge publish 门禁 4 + chat 反馈→考题闭环接线
7. 前端评测页 + 端到端验证(EV: 跑测试集出指标/闸门阻断发布/反馈生成考题)

## 8. 验收要点

| 编号 | 验收标准 |
|---|---|
| EV-01 | 建 5 条考题(X100 Pro 售后), 发起评测 → 任务 DONE, 输出各指标 + gatePass |
| EV-02 | 幻觉率>2% 的考题集(构造无据题) → 闸门 false, knowledge 发布被阻断(AC-010) |
| EV-03 | 指标达标考题集 → 发布放行 |
| EV-04 | 对话点踩 → ai_feedback 落库 → 自动生成考题(question=问题, source_feedback 关联) |
| EV-05 | 前端评测页: 考题 CRUD/发起任务/指标看板/逐题结果 |
| EV-06 | 阈值改 yaml 生效(如 recall 0.9→0.5, 判定随之变化) |

## 9. 生产级保证

- 评测复用 evidence.evaluate 完整链路(验证真实回答质量, 非孤立检索)
- 指标领域无关, 阈值全 yaml 可配
- 闸门硬性挂载发布(AC-010), 可配置开关
- 逐题结果落库(可重放/定位根因), 供评测与审计
- 反馈→考题自动生成(闭环⑥), 人工补标准答案后纳入回归
