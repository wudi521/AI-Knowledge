# 设计文档:问题槽位检测(问题完整性判断 + 动态槽位定义)

> 日期:2026-08-18 · 状态:用户确认(evidence 侧先行;chat 多轮闭环由另一任务承接, 不在本设计范围)
> 背景:证据平台 EV-01~EV-06 已交付。演示"我的手机坏了,可以免费维修吗?"暴露问题——问题缺品牌/故障类型/购机时间等关键信息时,系统不反问、直接给出"如果…如果…"的骑墙回答,既没解决歧义也没给下一步。
> 范围:evidence-server;**不碰** retrieval(纯搜索)、**不碰** chat(另一任务在建)。槽位定义**动态数据驱动**, 不写死在提示词里——换场景/加属性 = 插数据库行, 无需改代码。

---

## 1. 背景与目标

**问题一:问题歧义无感知。** 当前管线是单轮"问题→检索→评估→回答"。客户问"我的手机坏了,可以免费维修吗?"——品牌、故障性质、购机时间全缺失,系统不检测、不反问,直接基于通用保修条款给出分支式回答,客户无法据此行动。

**问题二:检测逻辑不可复用。** 已有的品牌一致性门禁(`SearchService` 第 12 步、`SufficiencyJudge` 实体覆盖)只处理"问题已明确产品但证据不符",且产品提取提示词(`QueryAnalysisService`)把意图类别、示例产品写死在提示词里。售后场景只是第一个场景,后面会有物流/退款/价格等——**必须让"要抽哪些属性"成为数据,而不是提示词**。

**成功标准**:
- `POST /evidence/evaluate` 输入歧义问题 → `answerable=false` + 结构化反问(`missingSlots` 缺失槽位列表 + `clarifyQuestion` 拼好的反问句),**不触发检索**, 仍落库留痕
- 槽位定义存 `ai_slot_definition` 表(租户隔离), 提供 admin CRUD API;运行期增删改/启停槽位**立即生效**, 无需改代码/重启
- 检测 LLM 调用失败 / 无槽位定义 / 租户缺失 → **降级为不检测**, 永不阻断原管线
- 槽位齐全的问题 → 照常走检索/评估, 原品牌一致性门禁**照常生效**(互补不冲突: 检测管"缺信息", 门禁管"信息不符")
- 预留 chat 多轮闭环接口: 检测结果字段(`extractedSlots`/`missingSlots`/`clarifyQuestion`)结构化输出, 供对话工作台展示反问、下一轮合并已补槽位后重评估

## 2. 架构(evidence 侧新增步骤 0, 原管线不动)

```
evidence-server(48087)
  EvidenceEvaluateController → EvidenceService(evaluate 编排)
    ├─ 0. SlotDetector(新增)  槽位检测(检索之前)
    │     ├─ 加载本租户 enabled 槽位定义(ai_slot_definition, 按 scene_code 分组)
    │     ├─ 无定义 → 跳过检测, 走原流程
    │     ├─ LLM: 注入"槽位定义 JSON + 问题" → {scene, extracted, missing}
    │     ├─ 失败/解析失败 → 降级不检测(log.warn)
    │     └─ 命中场景且 missing 非空 → answerable=false + 反问, 不检索, 落库, 返回
    ├─ 1. EvidenceAssembler   检索结果(Feign retrieval.search) → Evidence 列表
    ├─ 2. EvidenceDeduplicator  内容相似度去重
    ├─ 3. ConflictDetector     同主题证据矛盾判定
    ├─ 4. SufficiencyJudge     充分性判定(配置化规则 + 分数融合)
    ├─ 5. AnswerPipeline       生成回答 + Claim 逐句验证
    └─ 6. EvidenceRecorder     判定结果落库 ai_evidence_eval + ai_evidence
model-server(48091)      Feign: /chat(检测与生成共用模型网关)
```

**单次 LLM 调用设计**(与 `QueryAnalysisService` 结构化输出模式一致):
- 提示词模板固定, 槽位定义序列化为 JSON 注入(数据驱动)
- 输出 `{"scene": "AFTER_SALE" | null, "extracted": {"brand": "苹果13", ...}, "missing": [{"code":"faultType","name":"故障性质"}]}`
- scene=null(问题不属于任何已定义场景, 如"你好")→ missing=空 → 正常放行

## 3. 数据模型

### ai_slot_definition(新增, 租户隔离 TenantBaseDO)

| 列 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | 编号 |
| scene_code | varchar(64) | 场景编码(如 AFTER_SALE), 非空 |
| scene_name | varchar(64) | 场景名(如 售后维修), 非空 |
| slot_code | varchar(64) | 槽位编码(如 brand/faultType/purchaseTime), 非空 |
| slot_name | varchar(64) | 槽位名(如 品牌型号), 非空 |
| description | varchar(500) | 抽取说明(喂给 LLM 的抽取定义), 非空 |
| required | bit(1) | 是否必填(1=缺则反问, 0=选填不反问) |
| sort | int | 排序(组反问句顺序) |
| status | tinyint | 启停: 0=启用 1=禁用(CommonStatusEnum) |
| creator/create_time/updater/update_time/deleted/tenant_id | - | 审计字段(惯例) |

约束: 唯一键 `uk_scene_slot(scene_code, slot_code, deleted)`(同场景槽位编码唯一)。

### ai_evidence_eval(增量 3 列)

| 列 | 类型 | 说明 |
|---|---|---|
| slots | json | 本次抽取的槽位值 {"brand":"苹果13"} |
| missing_slots | json | 缺失必填槽位 [{"code":"faultType","name":"故障性质"}] |
| clarify_question | varchar(500) | 拼接好的反问句(answerable=false 且因缺槽位时填充) |

### 种子数据(AFTER_SALE 售后场景, 3 个必填槽位)

| scene_code | slot_code | slot_name | description | sort |
|---|---|---|---|---|
| AFTER_SALE | brand | 品牌型号 | 客户产品的品牌/型号(如 苹果13、X100 Pro) | 1 |
| AFTER_SALE | faultType | 故障性质 | 损坏原因: 意外损坏(摔落/进水/挤压)还是非人为质量问题 | 2 |
| AFTER_SALE | purchaseTime | 购机时间 | 购买时间或是否在保修期内 | 3 |

## 4. 接口

### admin 槽位定义 CRUD(权限 `evidence:slot-definition:*`)

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /evidence/slot-definition/create | 创建(含场景/槽位/必填/排序/启停) |
| PUT | /evidence/slot-definition/update | 更新 |
| DELETE | /evidence/slot-definition/delete?id= | 删除 |
| GET | /evidence/slot-definition/get?id= | 详情 |
| GET | /evidence/slot-definition/page | 分页(场景/槽位/启停筛选) |

### evidence evaluate 响应增量字段(EvidenceEvaluateRespVO + EvidenceEvaluateRespDTO 同步)

| 字段 | 类型 | 说明 |
|---|---|---|
| slotScene | String | 命中的场景编码(未命中/未检测为 null) |
| extractedSlots | List\<SlotValueVO{code,name,value}\> | 从问题中抽取的槽位值(审计/后续合并用) |
| missingSlots | List\<SlotValueVO{code,name}\> | 缺失的必填槽位 |
| clarifyQuestion | String | 拼好的反问句(如"请问您的手机是什么品牌型号?损坏是意外造成还是质量问题?购机多久了/是否在保修期内?") |

语义: `answerable=false` 且 `missingSlots` 非空 ⇒ 因缺信息反问;`refusalReason` = "需补充信息:品牌型号、故障性质、购机时间"。

## 6. 降级与边界

| 场景 | 行为 |
|---|---|
| slot.enabled=false | 跳过检测, 走原流程 |
| 本租户无 enabled 槽位定义 | 跳过检测 |
| 检测 LLM 调用异常/超时 | log.warn + 跳过检测(原流程) |
| LLM 输出 JSON 解析失败 | log.warn + 跳过检测(原流程) |
| RPC 路径 tenantId=null | 跳过检测(GUI/Controller 路径恒有登录态, 不受影响) |
| 槽位齐全 | 正常检索;原品牌一致性门禁照常生效 |
| 问题不属于任何场景 | scene=null → 放行 |
| 反问落库 | ai_evidence_eval 1 行(evidence_count=0), 不写 ai_evidence 证据行 |

**错误码**: 新增 `SLOT_DEFINITION_NOT_EXISTS = 1_007_000_002`(admin CRUD 用)。

## 8. 领域无关性保证

- 提示词模板固定(通用"抽取以下槽位"结构), 场景/槽位全部来自 `ai_slot_definition` 行
- 新增场景 = 插行(场景名/槽位/抽取说明), 删除/禁用 = 启停/删除行, 无需改代码或提示词
- 检测组件不感知"售后/保修"业务词汇, 一切由 description 定义驱动
