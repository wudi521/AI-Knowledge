## 1. 背景与目标

检索平台找证据、证据平台判能否作答,但**客户的问题还没人接**。对话工作台是 PRD 阶段 1 最小闭环的最后一环:

- 客户在网页发起对话 → AI 复用证据平台判定 → **可作答且验证通过 → 带引用回答**
- **答不了(证据不足/冲突/产品不匹配/Claim 失败/客户要求/情绪激烈)→ 自动转人工,交接带上下文摘要**
- 坐席在对话工作台查看 AI 建议 + 证据链 + 意图/实体,一键采纳或接管,全程留痕(BR-022)

**成功标准**:
- `POST /chat/chat/send`: 消息 → 判定 → 回答或转人工;`/conversation/transfer` `/take-over` 状态机;`/history` 会话记录
- ai_conversation 状态机 ACTIVE→TRANSFERRED→CLOSED;ai_message 落库含 citations JSON(引用证据)
- 转人工交接消息自动携带:原问题 + AI 建议 + 证据链摘要 + 意图/实体(AC-007)
- 前端对话工作台:会话列表 + 消息流 + AI 建议/证据面板 + 一键采纳 + 转人工/接管 + 会话记录
- 渠道抽象:ChannelAdapter 接口 + WEB 实现;企微/钉钉留适配器位(本地无法端到端验证, 不写假接入)

## 2. 架构

```
渠道层(ChannelAdapter)            chat-server(48083)
  WEB(真实) / WeCom(预留)  →  ChatController → ChatPipeline
  DingTalk(预留) / APP(预留)      ├─ ConversationService  会话状态机/落库
                                  ├─ MessageService       消息落库(含 citations)
                                  ├─ EvidenceRpcAdapter   调 evidence.evaluate(Feign)
                                  └─ TransferHandler      转人工触发+交接摘要+留痕
evidence-server(48087)  Feign: /evidence/evaluate(复用完整判定管线: 检索/去重/冲突/充分性/生成/Claim)
model-server(48091)     Feign: /chat(对话补全, 意图/情绪等辅助)
```

**判定管线(非流式, 完全复用证据平台)**:
```
客户消息 + 会话上下文
  → ① EvidenceRpcAdapter 调 evidence.evaluate(query, kbIds, topK)
  → ② 判定: answerable && answer != null && !claimFail → 返回答案(带 [C1] 引用)
  → ③ 否则 → TransferHandler: 会话置 TRANSFERRED, 组装交接消息(问题+AI建议+证据摘要+原因), 落库
  → ④ 全程落库 ai_message(USER/AI/SYSTEM 角色), 会话状态同步
```

## 3. 会话与消息模型(复用已有表, 增量字段)

**ai_conversation**(已有: channel/customer_id/status/intent + 审计字段):
- 状态机: `ACTIVE`(AI 服务中)→ `TRANSFERRED`(已转人工)→ `CLOSED`(已关闭/解决)
- 增量字段建议: `summary varchar(500)`(转人工交接摘要, 供坐席快速了解)、`transfer_reason varchar(200)`(转人工原因: 证据不足/冲突/产品不匹配/Claim失败/客户要求/情绪激烈)、`operator_id bigint`(接管坐席)

**ai_message**(已有: conversation_id/role/content/citations json + 审计字段):
- role: USER/AI/SYSTEM(转人工交接消息用 SYSTEM 或新增 ASSISTANT 语义——沿用现有枚举, 交接用 SYSTEM)
- citations json: 引用证据编号列表(证据平台返回的 chunkId 列表), 前端展开原文
- 增量字段建议: `intent varchar(64)`(本次消息意图)、`entities json`(实体列表)、`confidence decimal(5,4)`(充分度)、`trace_id varchar(64)`(证据平台链路追踪号, 关联 ai_evidence_eval)

## 4. 转人工(TransferHandler, 对齐 BR-015)

**触发条件**(任一满足即转人工, 原因随会话记录):
1. 证据不足: evidence.answerable=false, refusalReason 含"证据不足/未检索到"
2. 证据冲突: answerable=false, refusalReason 含"冲突"
3. 产品不匹配: answerable=false, refusalReason 含"产品不匹配"
4. Claim 验证失败: claimFail=true(生成后无据断言重试耗尽)
5. 客户要求: 消息含"人工/转人工/客服/投诉"等关键词(结构化规则, 非 LLM)
6. 情绪激烈: 消息含"太差/垃圾/投诉/赔偿/滚"等词(规则词表, 可配置)

**交接摘要**(AC-007): 自动生成 `summary` = 原问题 + AI 建议(有则附) + 证据链摘要(最多 3 条证据的文档名) + 转人工原因, 坐席打开会话即见, 无需重复询问。

**留痕**(BR-022): 转人工动作本身落 ai_message(SYSTEM, 含 summary);坐席"采纳/驳回/接管"操作记录到 ai_feedback 或会话轨迹字段(见 T4 细化)。

## 5. 渠道抽象(领域无关)

```java
public interface ChannelAdapter {
    String channel();                       // WEB / WECHAT / DINGTALK / APP
    ChannelMessage parse(Object raw);       // 渠道原始消息 → 统一消息模型
    void reply(String conversationId, ChatReply reply);  // 回写渠道(web=SSE/JSON; 企微=客服消息API)
}
```
- 本阶段实现 `WebChannelAdapter`(真实链路: HTTP 请求/响应即渠道);企微/钉钉适配器只留接口 + 配置位, 不写假实现
- 渠道 ID 入会话元数据(BR-021), 渠道级限流留配置位

## 6. 接口

`POST /chat/chat/send` `{conversationId?, message, channel?, customerId?}` → 返回:
```json
{ "conversationId": 1, "reply": "很遗憾... [C1]", "answerable": true,
  "confidence": 0.87, "citations": [2082], "traceId": "ev-xxx",
  "transferRequired": false }
```
- conversationId 为空 → 自动建会话(WEB 渠道);非空 → 续会话
- transferRequired=true 时 reply=null, 附 transferReason/summary

`POST /chat/conversation/transfer` `{conversationId, reason?}` → 手动转人工(坐席或客户要求)
`POST /chat/conversation/take-over` `{conversationId}` → 坐席接管(状态 TRANSFERRED→HANDLED? 或直接 CLOSED, 见 T4 状态机细化)
`GET /chat/conversation/history` `{conversationId}` → 消息列表 + 会话信息(含 summary/transferReason)
`GET /chat/conversation/page` → 会话分页(坐席工作台列表: 状态筛选/未接转移人工优先)

权限: `chat:chat:send` / `chat:conversation:transfer` / `chat:conversation:take-over` / `chat:conversation:query`

## 7. 前端对话工作台(vben5, web-antd)

改造 `views/ai/workbench-vben/index.vue`(现有 729 行 mock 页)为真实链路:
- **会话列表**: 调 /conversation/page, 状态徽标(ACTIVE/TRANSFERRED/CLOSED), 转人工待接优先置顶
- **消息流**: 用户/AI/系统消息气泡;AI 消息展示引用证据角标(点击展开原文, 复用检索页证据卡片样式)
- **AI 建议 + 证据面板**: 当前消息的 answerable/confidence 进度条/意图/实体/证据列表(复用证据评估面板组件)
- **一键采纳**: AI 建议采纳按钮 → 记录采纳(BR-022 留痕)→ 提示"已采纳"
- **转人工/接管**: 消息输入区"转人工"按钮(手动触发);TRANSFERRED 会话显示交接摘要卡片 + "接管"按钮 → 接管后状态更新, 坐席可继续回复
- **会话记录**: 历史消息完整可查

## 8. 实施顺序(单计划 7 任务)

1. 接线: chat-server pom + RpcConfiguration(EvidenceApi/ModelApi/KnowledgeApi)+ evidence-api 补真实 RPC(evaluate 的 Req/Resp DTO + EvidenceApiImpl 委托 EvidenceService)+ yaml 配置块 + DDL 增量(ai_conversation/ai_message 加列)
2. ConversationService + MessageService: 会话状态机/建会话/消息落库(含 citations/intent/confidence/trace)
3. ChatPipeline: send 编排(建/续会话 → 调 evidence → 判定 → 回答或转人工)+ EvidenceRpcAdapter
4. TransferHandler: 转人工触发规则(5 类)+ 交接摘要 + 留痕;手动 transfer/take-over

6. 前端对话工作台: 改造 workbench-vben 接真实 API(会话列表/消息流/证据面板/采纳/转人工接管)
7. 端到端验证: AC-005(低置信转人工)/ AC-006(Claim失败转人工)/ AC-007(交接上下文)/ 正常问答带引用 / 落库留痕

## 10. 领域无关性保证

- 渠道/会话/消息/转人工均为通用抽象, 无行业硬编码
- 转人工关键词/阈值走配置(yaml), 换行业只改配置
- 判定完全复用证据平台(领域无关管线), chat 只做编排与状态
- 输出结构化 + 全落库, 供评测/审计消费
