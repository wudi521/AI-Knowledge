# 设计文档:多轮对答与上下文(生产级)

> 日期:2026-08-18 · 状态:用户确认(生产级, 非轻量拼接)
> 前置:对话工作台已交付(单轮);证据平台已交付(判定管线);检索平台已交付(查询分析)
> 目标:连续追问正确作答(指代消歧)、历史结构化存储与传递、上下文截断与 token 控制、可观测(每轮完整留痕)

---

## 1. 现状与差距

| 能力 | 现状 | 生产级目标 |
|---|---|---|
| 历史存储 | ✅ ai_message 全落库 | ✅ + 会话级上下文快照/摘要字段 |
| 多轮对答 | ❌ 单轮: 每次 send 独立评估 | 带历史消歧 + 生成保持指代一致 |
| 上下文注入 | ❌ 无 | 结构化传递: chat→evidence→retrieval/生成 |
| 截断控制 | ❌ max-context-messages 未生效 | 生效: 轮数截断 + 字符截断 + 按角色过滤 |
| 可观测 | ❌ 无上下文视角 | 每轮评估落库带 history 快照(trace 可重放) |

## 2. 架构(上下文贯穿链路)

```
客户(第N轮消息) 
  → chat-server ChatPipeline
      ├─ 读会话历史: 最近 max-context-messages 轮 USER/AI(排除 SYSTEM 交接消息)
      ├─ 构造 ContextualQuery = {query: 当前消息, history: [{role,content}...]}
      └─ 调 evidence.evaluate(query, history)
  → evidence-server EvidenceService
      ├─ 透传 history 给检索: RetrievalSearchReqDTO.history
      └─ 透传 history 给生成: AnswerGenerator / ClaimVerifier prompt 附历史
  → retrieval-server SearchService
      └─ QueryAnalysis.analyze(query, history): LLM 结合历史消歧
          "那换屏多少钱" + 历史"X100 Pro 碎屏能免费修吗" → products=[X100 Pro], rewrites 含"X100 Pro 换屏价格"
  → evidence AnswerGenerator: prompt 附历史, 回答"换屏一口价 ¥699" 指代一致
```

**关键原则(生产级)**:
- 历史是**结构化数据**(role/content 列表), 不是拼字符串——各环节按需格式化
- **消歧发生在检索前**(QueryAnalysis 输入含历史, 输出完整改写), 检索本身不带历史(避免污染 BM25)
- 生成/验证带历史(保持指代), 但**历史不进证据判定**(充分性/冲突只对当轮 query 判定)
- 截断三级: 轮数(max-context-messages)→ 每轮长度(200字/条)→ 总长度(2000字)

## 3. 数据模型

**ai_message**(已有): role/content/citations/intent/entities/confidence/trace_id — 即历史来源, 不改。

**ai_conversation**(增量):
- `context_summary varchar(1000) NULL` — 会话级上下文摘要(转人工交接/坐席接管时快照最近 N 轮要点, 由 LLM 压缩或规则拼接)
- `message_count int NOT NULL DEFAULT 0` — 消息计数(前端/统计用)

**evidence_eval 落库**(增量, 可观测):
- `history json NULL` — 本次评估使用的上下文快照([{role,content}...]), 供重放/审计(评测平台消费)

## 5. 消歧实现(QueryAnalysis, 生产级)

**prompt 改造**: system 提示词加"上下文"输入区, user 消息结构:
```
历史对话(按时间顺序, 最新在前或在后):
[用户] X100 Pro 碎屏能免费修吗
[客服] 不能, 属意外损坏…
当前问题: 那换屏多少钱?
```
要求: rewrites 必须把指代词(那/它/这个/多少钱)结合历史展开为完整语义; products/entities 从历史继承缺失项。

**结构化兜底(规则层)**: LLM 分析失败 → 若历史非空, 把当前问题原样 + 最近一条 USER 消息拼接为 rewrite("换屏多少钱" → "X100 Pro 碎屏 换屏多少钱"), 保证降级也有基本消歧。

## 6. 生成带历史(AnswerGenerator / ClaimVerifier)

- AnswerGenerator.generate(query, evidences, history): prompt 附"历史对话(供指代理解, 不要复述)", 回答仍只依据当轮证据
- ClaimVerifier.verify(query, answer, evidences, history): 同上(历史仅帮助理解指代, 断言支撑只看证据)
- 生产约束: 历史截断后注入, 不超 prompt 上限

## 7. 上下文读取与截断(ChatPipeline)

```java
// 读最近 max-context-messages 条 USER/AI 消息(排除 SYSTEM), 按 create_time asc 排序
List<AiMessageDO> recent = messageService.getRecentMessages(conversationId, maxContextMessages);
// 截断: 每条 content ≤ 200 字, 总 ≤ 2000 字(超则丢弃最旧)
List<ChatTurnDTO> history = buildHistory(recent);
```
- max-context-messages 读自配置 `yudao.chat.max-context-messages`(已有 yaml, 补 @ConfigurationProperties 绑定)
- **SYSTEM 交接消息不进上下文**(它们是运维记录, 非对话)

## 8. 会话上下文摘要(转人工/接管时)

- TransferHandler.buildSummary 增强: 附"近 N 轮对话要点"——从会话历史取最近 3 条 USER+AI 消息规则拼接(不调 LLM, 生产稳)
- 存 ai_conversation.context_summary, 坐席面板展示

## 9. 实施顺序(单计划 6 任务)

1. DTO 链路: evidence-api/retrieval-api 加 ChatTurnDTO + history 字段;EvidenceService/Assembler/SearchService/QueryAnalysis 签名重载透传;evidence-eval 落库 history 快照(json)
2. QueryAnalysis 消歧: prompt 加历史区 + 结构化兜底拼接;单元级验证(那/它消歧)
3. 生成带历史: AnswerGenerator/ClaimVerifier prompt 附历史(截断后);AnswerPipeline 透传
4. ChatPipeline 上下文: 读最近消息 → 截断 → 构造 history → 传 evaluate;max-context-messages 绑定生效;ConversationService 消息计数 + context_summary 增量 DDL
5. TransferHandler 摘要增强: 附近轮对话要点 → context_summary;落库
6. 端到端验证: 多轮追问("碎屏能免费修吗"→"那换屏多少钱"→正确答 ¥699)/ 指代消歧 / 历史落库可查 / 超长上下文截断不报错 / 单轮向后兼容

## 10. 验收要点

| 编号 | 验收标准 |
|---|---|
| MC-01 | 轮1"X100 Pro 碎屏能免费修吗"(答: 不能) → 轮2"那换屏多少钱?" → 答含 ¥699 换屏(指代正确, 不答非所问) |
| MC-02 | 轮2 的 evidence_eval 落库 history 快照含轮1 对话, trace 可重放 |
| MC-03 | 历史含 SYSTEM 交接消息时被过滤, 不进上下文 |
| MC-04 | 超长会话(>max-context-messages 轮) → 截断生效, 只带最近 N 轮, 不报错 |
| MC-05 | 单轮调用(无 history)行为与改造前一致(向后兼容) |
| MC-06 | 转人工交接摘要含近轮对话要点(context_summary 落库) |

## 11. 生产级保证

- 历史结构化传递, 各环节按需格式化, 不拼脏字符串
- 消歧前置(检索前), 检索纯净;生成带历史但判定不带
- 三级截断(轮数/条长/总长) + 角色过滤(SYSTEM 排除)
- 全链路落库(history 快照 + context_summary), 供评测/审计/重放
- 向后兼容: 所有新参数可选, 旧调用行为不变
