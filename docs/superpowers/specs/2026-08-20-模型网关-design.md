# 设计文档:模型网关 M6-A(生产级)

> 日期:2026-08-20 · 状态:用户确认(生产级规范; 场景多样化, 不以售后为验收锚点)
> 前置:PRD《M6 AI 运行时·模型网关》(BR-017 路由/降级/限流/超时重试/计量); 对账文档《PRD对账与缺口清单.md》
> 定位:M6 第一块, 也是 M8 成本管理的地基。**领域无关**——不感知售后/物流/HR 等任何行业语义, 只做"模型注册 → 路由 → 调用 → 可靠性 → 计量"。

---

## 1. 目标与非功能需求

**目标**: 多模型注册、按 (租户, 类型, 场景) 路由、降级重试、Token 计量; 换模型/换场景/换租户只改配置不改代码。

**非功能需求(生产级, 均纳入验收)**:
| 维度 | 要求 |
|---|---|
| 可靠性 | 超时控制(连接/读可配); 瞬态错误重试(指数退避); 主→备降级; 连续失败熔断+半开恢复 |
| 可观测性 | 全量调用计量落库(状态/耗时/字符/tokens); traceId 透传; 健康检查暴露各模型状态 |
| 安全 | apiKey 配置化且**不落日志/不落计量表**; 计量表脱敏; 租户数据隔离 |
| 多租户 | 路由 tenant 优先, 无租户配置回退默认; 计量按租户归属 |
| 成本 | est_tokens 计量(真实 usage 优先); M8 成本管理直接消费 ai_model_call_log |
| 性能 | 计量异步落库不阻塞调用; HTTP 连接复用 |
| 兼容 | ModelApi 接口不变, 消费方零改动; DB 无匹配时回退现有 yaml 默认 |

## 2. 架构

```
消费方(retrieval/evidence/knowledge/eval/chat)
  └─ Feign ModelApi(chat/embedding/rerank + 可选 scenario/traceId)
model-server(4809x)
  ModelApiImpl ──> ModelGateway(核心编排)
    ├─ ModelResolver   路由: (tenant,type,scenario) → 候选模型列表(按 priority)
    │                    租户配置优先 → 场景配置 → '*' 默认 → yaml 兜底
    ├─ ModelInvoker    OpenAI 兼容 HTTP 调用(LM Studio/llama.cpp/OpenAI 兼容)
    │                    provider 字段留适配器位(MVP 仅 openai-compatible)
    ├─ RetryPolicy      瞬态错误(超时/5xx)重试 N 次指数退避; 4xx 不重试
    ├─ CircuitBreaker   单模型连续失败阈值 → 短路窗口 → 半开探测(进程内计数)
    ├─ FallbackRouter   主候选失败 → 下一候选
    └─ CallMeter        计量 → ai_model_call_log(异步, 失败不阻断)
注册表: ai_model_config(已有表 + scenario/priority 列)
配置:   租户级模型配置(同表 tenant 隔离) / yaml 默认兜底
```

## 3. 数据模型

### ai_model_config(增量 2 列; 现有列: id/name/type/provider/modelName/baseUrl/apiKey/dimensions/status/remark)

| 列 | 说明 |
|---|---|
| scenario | varchar(64) NOT NULL DEFAULT '*' — 场景标识; '*'=默认场景 |
| priority | int NOT NULL DEFAULT 0 — 同 (type,scenario) 内降级顺序, 小者优先 |

路由解析: `(tenant_id, type, scenario)` → `(tenant_id, type, '*')` → `(0, type, scenario)` → `(0, type, '*')` → yaml 兜底。每级取 status=启用 且按 priority 升序的列表。

### ai_model_call_log(新建)

| 列 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | 编号 |
| trace_id | varchar(64) | 调用方透传链路追踪号(可空) |
| tenant_id | bigint | 租户(成本归属) |
| scenario | varchar(64) | 路由场景(缺省 '*' 或实际命中值) |
| type | varchar(16) | chat / embedding / rerank |
| model_id | bigint | 实际命中的模型配置编号 |
| model_name | varchar(128) | 实际模型名快照 |
| provider | varchar(32) | 供应商快照 |
| prompt_chars | int | 输入字符数(chat=system+user; embedding=文本拼接; rerank=query+docs) |
| completion_chars | int | 输出字符数(embedding/rerank 为 0) |
| prompt_tokens | int | 计量 token(真实 usage 优先, 否则估计) |
| completion_tokens | int | 同上 |
| elapsed_ms | int | 单次调用耗时(含重试前的单次尝试? 设计: 记录单次尝试, 多次尝试各自一行) |
| status | varchar(16) | SUCCESS / FAILED(重试耗尽/4xx) / DEGRADED(降级到备选成功) |
| error_msg | varchar(500) | 失败原因(截断; **不含 apiKey**) |
| attempt | int | 第几次尝试(1=首次) |
| create_time | datetime | 创建时间(审计) |

token 估计法(注释说明): `est_tokens = ceil(chars / 1.5)`(中文为主的经验值; provider 返回 usage 时优先真实值)。
apiKey **永不**写入本表。

## 4. 接口

- `ModelApi` 不变: `embedding(List<String>)` / `chat(ModelChatReqDTO)` / `rerank(ModelRerankReqDTO)`
- DTO 增量(可选, 向后兼容): `ModelChatReqDTO.scenario` / `.traceId`(已有 temperature); embedding/rerank 加 scenario/traceId
- admin: `AiModelConfigController` 现有 CRUD + SaveReqVO 加 scenario/priority(校验 type+scenario 组合)

## 5. 失败模式与降级矩阵

| 场景 | 行为 |
|---|---|
| 主模型超时/5xx/网络错 | 重试 1 次(指数退避 200ms/400ms)→ 仍失败降级下一候选 |
| 4xx(参数/鉴权) | 不重试, 直接抛错(重试无意义) |
| 全候选失败 | 抛 ServiceException(调用方按现状降级: 证据空/回答 null 等) |
| 熔断(某模型连续失败 ≥5 次) | 短路 30s 直接走备选; 半开放 1 个探测请求 |
| 计量落库失败 | log.warn, 不阻断调用 |
| DB 无匹配模型 | yaml 默认兜底(存量部署不破坏) |
| 未配置任何模型 | 启动不失败, 调用时报明确错误 |

## 6. 安全

- apiKey: yaml/DB 配置, 日志与计量表脱敏(不打印、不落库)
- 多租户: 模型配置与计量均 TenantBaseDO; 路由不跨租户
- 计量表 error_msg 截断且过滤敏感字段
- 网关不做 prompt 注入防护(那是上层语义安全, 记为 M 系列后续)

## 7. 可观测性

- ai_model_call_log 全量(成功/失败/降级/耗时/字符/tokens)
- `GET /model/health` 扩展: 每个启用模型可达性探测(轻量调用或 TCP), 状态可见
- traceId 从调用方透传, 贯穿计量行, 供 M8 链路快照关联

## 8. 多场景验收(不以售后为锚点)

| 编号 | 场景 | 步骤 | 期望 |
|---|---|---|---|
| MG-01 | 路由 | 配 3 场景(A/B/默认)×chat 各 1 模型; 分别以 scenario=A/B 调用 | 各自命中对应模型; 无 scenario 走默认 |
| MG-02 | 降级 | 场景 A 主模型地址指向不可达端口, 配 1 备 | 主超时/失败 → 重试 → 降级备选成功, 计量 status=DEGRADED |
| MG-03 | 熔断 | 主模型连续失败 ≥5 次 | 短路窗口内直接走备选; 半开探测恢复 |
| MG-04 | 计量 | 跨 3 租户/3 场景调用 | ai_model_call_log 按租户/场景/模型准确归属, token/耗时/状态正确 |
| MG-05 | 兼容 | 存量调用不带 scenario/traceId | 走默认路由, 行为与现状一致 |
| MG-06 | 通用链路 | 物流政策库(非售后): 问"跨区配送时效" | 检索→证据→回答全链路正常, 计量落库 |
| MG-07 | 通用链路 | HR 政策库: 问"年假怎么算" | 同上(证明领域无关, 非售后定制) |
