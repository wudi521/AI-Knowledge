# 设计文档:知识库级动态意图体系

> 日期:2026-08-18 · 状态:用户确认(知识库级意图 + 超范围转人工 + 发布时自动总结)
> 前置:检索平台(QueryAnalysis 固定 6 枚举意图)、证据平台、对话工作台(转人工机制)、知识治理(发布版本)
> 目标:意图跟知识库内容走——发布时 LLM 自动总结 + 手动管理;问题意图超出知识库范围 → 不检索不硬答, 转人工

---

## 1. 现状与问题

- QueryAnalysis 意图是**写死的 6 枚举**(WARRANTY/REFUND/LOGISTICS/REPAIR/PRICE/OTHER), 只用于展示, 不驱动行为
- 用户问"换手机有什么推荐"(产品推荐) → 归为 OTHER → 检索强行召回售后片段 → LLM 硬答"建议联系官方客服"——**知识库不覆盖的问题被硬答**
- 意图与实际知识库内容脱节: 售后库有保修/退款意图, 产品库有推荐/参数意图, 固定枚举表达不了

## 2. 目标

| # | 能力 |
|---|---|
| 1 | 意图按知识库配置(每个库自己的意图集), 存储 ai_intent 表 |
| 2 | 发布版本时 LLM 扫描该版本 chunks 自动总结意图(增量更新该库意图) |
| 3 | 手动管理: 意图 CRUD + "重新总结"按钮(LLM 重扫) |
| 4 | 检索/评估用**对应知识库的意图集**分类, 而非固定枚举 |
| 5 | 问题意图不在任何已配置意图范围 → **超范围**: 不检索不硬答, 转人工/明说无资料 |

## 3. 数据模型

**ai_intent**(新表, 知识库级):
```sql
CREATE TABLE ai_intent (
  id bigint NOT NULL AUTO_INCREMENT COMMENT '编号',
  kb_id bigint NOT NULL COMMENT '知识库编号',
  name varchar(64) NOT NULL COMMENT '意图名(如 保修/退款/产品推荐)',
  description varchar(500) NULL COMMENT '意图说明(LLM 总结或手填, 供分类参考)',
  source varchar(16) NOT NULL DEFAULT 'MANUAL' COMMENT '来源: LLM_AUTO/MANUAL',
  status tinyint NOT NULL DEFAULT 0 COMMENT '状态: 0启用/1停用',
  creator/create_time/updater/update_time/deleted/tenant_id,
  PRIMARY KEY (id), KEY idx_kb (kb_id)
) COMMENT='AI 知识库意图';
```

**ai_knowledge_base**(增量): 不加列——意图独立表关联, 避免冗余。

## 4. LLM 自动总结(发布时触发)

- **触发点**: knowledge-server 版本发布成功后(publish 方法, 幂等: 每次发布更新该库意图——决策: 发布成功即触发 LLM 总结, 覆盖式重建该库意图列表)
- **实现**: IntentSummarizer(@Component, ModelApi): 取该版本已发布 chunks 的 content(截断: 最多 20 条 × 200 字), system prompt:
  ```
  你是知识库意图分析师。根据下方知识库内容, 总结该知识库能回答的客户意图分类(2~8 个),
  每个意图给出简短说明。只输出 JSON: {"intents":[{"name":"保修","description":"保修期、免费维修政策"}]}
  ```
- **结果**: 覆盖该 kb 的全部意图(MANUAL 与 LLM_AUTO 都覆盖?决策: 发布自动总结仅写入 LLM_AUTO 且**不删除 MANUAL 条目**——LLM 条目标记来源, 管理员可停用/删除; 或"覆盖全部"?——选**保留 MANUAL, 刷新 LLM_AUTO**: 手动条目管理员权威, 自动条目随版本刷新)
- **失败降级**: LLM 总结失败/解析失败 → log.warn, 保留旧意图不动(不阻断发布——发布已成功, 总结是后置增强)
- **异步**: 发布成功后异步执行(不阻塞发布响应); 落 ai_intent 事务

## 5. 意图分类(检索/评估用知识库意图集)

**QueryAnalysisService 改造**:
- 输入增加 `List<IntentDTO> intents`(对应知识库的意图配置, retrieval 侧从 knowledge RPC 拉取 `getKbIntents(kbId)`)
- system prompt 动态注入意图列表:
  ```
  意图分类(从以下知识库意图中选择最匹配的一项; 都不匹配则输出 "OUT_OF_SCOPE"):
  - 保修: 保修期、免费维修政策
  - 退款: 退货退款流程
  - 产品推荐: 换机、选购建议
  ```
- 输出 intent 为配置中的 name 或 OUT_OF_SCOPE
- 单轮兼容: 无意图配置 → 退化为"不指定意图, 自由分析"(或保留内置枚举?决策: 无配置时 intent=null 不分类, 不判超范围)

**超范围判定(结构化)**:
- analysis.intent == "OUT_OF_SCOPE" → SearchService 短路: 不检索、answerBlocked=true、answerReason="问题超出该知识库服务范围(意图: 未匹配), 已转人工"、results 空
- evidence 侧: retrieval 返回 answerBlocked → SufficiencyJudge 直接 answerable=false(已有检索阻断路径)
- chat 侧: 转人工 reason="超出知识库范围"

## 6. 接口

**knowledge-server**:
- `GET /knowledge/intent/list?kbId=` → 该库意图列表(含 source/status)
- `POST /knowledge/intent/create` `{kbId, name, description}` → 手动新增(MANUAL)
- `PUT /knowledge/intent/update` `{id, name, description, status}` → 手动编辑/停用
- `DELETE /knowledge/intent/delete?id=` → 删除(仅 MANUAL?决策: 都可删, 删后发布重扫会重建 LLM_AUTO)
- `POST /knowledge/intent/summarize?kbId=` → 手动触发 LLM 重扫(返回新意图数)
- RPC: `KnowledgeApi.getKbIntents(kbId) → List<IntentDTO>{name, description}`(retrieval 用; 只返回启用条目)

**retrieval-server**: 无新接口;QueryAnalysis 内部用 RPC 拉意图
**chat-server**: 无新接口;超范围转人工沿用 transferReason="超出知识库范围"

## 7. 前端(知识库详情/管理页)

- 知识库列表行操作加"意图管理"(或知识库编辑弹窗加 Tab)
- 意图管理面板: 列表(名称/说明/来源 Tag LLM自动|手动/状态开关)+ 新增/编辑/删除 + "重新总结"按钮(调 summarize, 展示结果)
- 检索测试页: intent 展示改为动态名称;OUT_OF_SCOPE 显示红色"超出知识库范围"徽标 + 拒绝卡片

## 8. 实施顺序(单计划 7 任务)

1. DDL + DO/Mapper + IntentService(CRUD)+ IntentController + 菜单/权限(ai_intent 表; 权限 knowledge:intent:*)
2. IntentSummarizer: 发布时 LLM 总结(异步, 幂等, 降级不阻断)+ KnowledgeApi RPC getKbIntents
3. QueryAnalysis 动态意图: 拉取知识库意图 → prompt 注入 → intent=name|OUT_OF_SCOPE;无配置兼容
4. 超范围短路: SearchService OUT_OF_SCOPE → 不检索/answerBlocked/空结果;evidence 传导(answerable=false);chat 转人工 reason=超出知识库范围
5. 手动 summarize 接口 + 发布触发接线(publish 后异步)
6. 前端意图管理(知识库行"意图管理"+ 面板 CRUD + 重新总结 + 状态开关)+ 检索页 OUT_OF_SCOPE 展示
7. 端到端验证: 发布后意图自动总结 / 手动管理 / "换手机推荐"→超范围转人工不硬答 / 售后问题正常分类 / 无配置库兼容

## 9. 验收要点

| 编号 | 验收标准 |
|---|---|
| IT-01 | 发布版本后 ai_intent 自动生成该库意图(LLM_AUTO, 2~8 个, 含名称+说明) |
| IT-02 | 手动新增/编辑/停用/删除意图生效;重新总结不删 MANUAL 条目 |
| IT-03 | 问"碎屏能免费修吗" → 命中"保修"意图, 正常回答 |
| IT-04 | 问"换手机有什么推荐" → OUT_OF_SCOPE → 不检索不硬答, 转人工 reason=超出知识库范围 |
| IT-05 | 未配置意图的知识库 → 退化为自由分析, 不误判超范围 |
| IT-06 | 检索页展示动态意图名;OUT_OF_SCOPE 红色徽标 |

## 10. 生产级保证

- 意图是数据不是代码(知识库级, 增删改查+LLM 总结)
- LLM 总结降级不阻断发布(异步+失败保留旧意图)
- 超范围判定结构化(不靠 LLM 提示词硬约束, 意图集来自配置)
- 向后兼容: 无意图配置的库行为不变
