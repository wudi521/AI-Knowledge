# 证据平台(领域无关判定管线)实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** evidence-server(48087)落地通用证据判定管线:检索结果组装证据 → 去重 → 冲突检测 → 充分性判定(answerable/confidence)→ 生成回答 + Claim 逐句验证 → 落库留痕;阈值全部 yaml 配置,领域无关。

**Architecture:** evidence-server 编排;Feign 调 retrieval.search(复用混合检索/品牌门禁)、model.chat/rerank;SufficiencyJudge 用配置化权重融合 confidence;ClaimVerifier 重试 ≤2;判定结果落 ai_evidence_eval(会话级)+ ai_evidence(证据级)。

**Spec:** `docs/superpowers/specs/2026-08-18-证据平台-design.md`

## 环境前提
- retrieval-server 检索链路已交付(POST /admin-api/retrieval/search 返回 analysis/channels/answer/answerBlocked/results[chunkId,content,documentName,versionNo,rrfScore,rerankScore,channels])
- model-server: /chat(qwen3-8b, reasoning_effort=none)/embedding/rerank(llama.cpp 1236)
- evidence-server 骨架已有(48087);gateway 路由 `/admin-api/evidence/**` 需确认(缺则加)

## 任务

### Task 1: 接线 + DDL + 配置块
- evidence-server pom: + retrieval-api/model-api/knowledge-api(均 cn.iocoder.cloud ${revision});RpcConfiguration 登记 RetrievalApi/ModelApi/KnowledgeApi
- DDL(MySQL): 新建 `ai_evidence_eval`(trace_id/query/answerable/confidence/refusal_reason/evidence_count/conflict_count/answer/claim_pass/claims json/conflicts json/elapsed_ms + 审计字段);ai_evidence 表已有(chunk_id/confidence/verdict/trace_id)不动
- application-local.yaml: `yudao.evidence.sufficiency.{answer-threshold:0.75, consult-threshold:0.5, min-evidence-count:2, entity-consistency:true, conflict-block:true, weights:{top-score:0.5,evidence-count:0.3,entity-coverage:0.2}}`, `yudao.evidence.dedup.similarity-threshold:0.85`, `yudao.evidence.claim.max-retry:2`
- 编译 + 启动验证(health)

### Task 2: EvidenceAssembler + EvidenceDeduplicator
- `Evidence{chunkId, content, documentName, versionNo, score, products, channels}`(DTO)
- EvidenceAssembler: Feign retrieval.search(query, kbIds, topK=8) → results → Evidence 列表;同时把 retrieval 的 analysis/answerBlocked/answerReason 一并透出(供上游判定)
- EvidenceDeduplicator: 字符重叠相似度(去重合并保留高分);> 阈值合并, 输出去重后列表 + 去重数

### Task 3: ConflictDetector
- 同主题候选:两两证据字符重叠 ≥ 0.5 视为同主题对
- LLM 结构化判定:chat → `{"conflict":true/false,"reason":"...","pair":[i,j]}`, 一次调用传所有候选对(≤10 对, 截断)
- 失败 → 按无冲突(log warn);输出 `Conflict{evidenceIndexA, evidenceIndexB, reason}` 列表

### Task 4: SufficiencyJudge
- 输入:去重后证据 + 冲突列表 + 问题产品(retrieval analysis 或 evidence 内提取)
- 指标:top-score(最高证据分归一化: rerank 分经 min-max 到 0~1, 负分截 0)、evidence-count(证据数/期望数, 期望=min-evidence-count)、entity-coverage(证据产品覆盖问题产品?1:0;无问题产品=1)
- confidence = Σ weight × 指标;冲突且 conflict-block → answerable=false;产品不匹配且 entity-consistency → answerable=false
- 输出:answerable/confidence/reason(不充分/冲突/产品不匹配时给原因)

### Task 5: AnswerGenerator + ClaimVerifier
- AnswerGenerator: 基于证据生成带 [C1] 引用的回答(提示词:只依据证据/标注引用/产品一致——但产品一致已由门禁保证)
- ClaimVerifier: 一次 chat 输出 `{"claims":[{"text":"...","verdict":"SUPPORTED|UNSUPPORTED","evidenceIndex":1}]}`;全 SUPPORTED → 通过;有 UNSUPPORTED → 重试生成(≤max-retry, 提示无据句);仍失败 → claimFail=true, answer=null

### Task 6: EvidenceService 编排 + Controller + VO + 落库
- EvidenceService.evaluate(query, kbIds, topK): 检索 → 组装 → 去重 → 冲突 → 充分性 → (可作答?生成+验证) → 落库 → 响应
- VO: EvaluateReqVO{query,kbIds,topK}; EvaluateRespVO{traceId,query,answerable,confidence,refusalReason,evidence[],conflicts[],answer,claims[],claimFail}
- EvidenceRecorder: 写 ai_evidence_eval(1 行)+ ai_evidence(每证据 1 行, verdict 记 SUPPORTED/冲突/无关)
- Controller: POST /evidence/evaluate, @PreAuthorize("evidence:evaluate")

### Task 7: 前端证据面板
- 检索测试页下方"证据评估"区:调 /evidence/evaluate 展示:充分性徽标(answerable/拒绝原因)+ 置信度进度条 + 冲突红标 + Claim 逐句(✓/✗)+ 证据列表(展开原文)
- api/ai/evidence/index.ts + 页面组件;菜单/按钮沿用检索页(不做新菜单, 检索页内联展示)

### Task 8: 端到端验证
- EV-01 充分作答 / EV-02 产品不匹配 / EV-03 冲突 / EV-04 无据断言拦截 / EV-05 落库 / EV-06 阈值配置生效
- 验证命令见设计文档 §10

- 落库:ai_evidence_eval 会话级 + ai_evidence 证据级
