## 任务

### Task 1: 接线 + DDL + 配置块
- eval-server pom: + evidence-api/knowledge-api(无 retrieval-api 直接依赖, evidence 内部已调检索);RpcConfiguration 登记 EvidenceApi/KnowledgeApi/EvalApi
- DDL: 新建 `ai_eval_result`(task_id/case_id/answerable/confidence/recall_at_5/mrr/ndcg/faithfulness/hallucination_rate/citation_accuracy/passed/fail_reasons/answer/trace_id + 审计);`ALTER ai_eval_case ADD kb_id bigint NULL, ADD category varchar(32) NULL`;`ALTER ai_eval_task ADD kb_id bigint NULL, ADD case_count int, ADD start_time datetime, ADD end_time datetime, ADD gate_pass tinyint, ADD fail_cases json`
- application-local.yaml: `yudao.eval.gate.{enabled:true, recall-at-5:0.9, mrr:0.8, ndcg:0.8, faithfulness:0.95, hallucination:0.02, citation-accuracy:0.97}` + `yudao.eval.runner.{max-parallel:2, timeout-ms:300000}`
- gateway 路由 `/admin-api/eval/**` 确认/补
- 编译 + 启动验证(health)

### Task 2: EvalCaseService(考题 CRUD + 反馈生成)
- EvalCaseDO/Mapper(BaseMapperX + TenantBaseDO)
- EvalCaseService: create/update/delete/page/get;create 校验 question 非空 + gold_chunks JSON 格式
- EvalCaseController: POST /eval/case/create|update, DELETE /eval/case/delete?id=, GET /eval/case/page|get
- 反馈生成: EvalApi.generateCaseFromFeedback(feedbackId) → 查 ai_feedback(chat 侧表?确认归属模块——若 feedback 表在 chat 模块, 则 eval 需 chat-api 或直接由 chat 侧调 eval 创建考题; 决策: EvalApi 提供 createCaseFromFeedback(kbId?, question, sourceFeedbackId), chat 侧 feedback 落库后调它)
- 菜单/权限: eval:case:query/create/update/delete (parent 2758, type 3)
- 编译 + 冒烟(CRUD)

### Task 3: EvalRunner(评测执行器)
- EvalTaskDO/Mapper(EvalTaskMapper)
- EvalRunner(@Component + EvidenceApi): runTask(taskId): 取任务考题列表 → 逐题(串行或并行≤2)调 evidenceApi.evaluate(query, kbIds, topK=8, tenantId, userId) → 每题结果组装(evidence 顺序/answer/claims/citations/answerable/confidence)暂存 → 落 ai_eval_result
- 异步执行: 专用线程池(评测不阻塞 HTTP);状态 RUNNING→DONE/FAILED
- 失败降级: 单题 evidence 异常 → 该题 passed=false + reason"评估异常", 不中断整批
- 编译 + 冒烟(单题 evaluate 可达)

### Task 4: MetricCalculator(指标计算)
- 纯静态工具(可单测): 输入(题: goldChunks[], results: 按重排分降序的 chunkId[], answer, claims[], citations[]) → 输出指标
  - recallAt5 = |gold ∩ top5| / |gold|
  - mrr = 1/firstHitRank(gold 首个在 results 中的排名; 无 → 0)
  - ndcg@5 = 按 gold 命中的增益衰减累计 / 理想 DCG
  - faithfulness = SUPPORTED claims / 总 claims(无 claims → 0)
  - hallucinationRate = UNSUPPORTED / 总(无 claims → 0)
  - citationAccuracy = |引用指向 chunk ∈ gold| / 总引用(无引用 → 0)
- 阈值判定: 每题 passed = 全指标达标(yaml 阈值)
- 编译 + 单元验证(构造样例算指标)

### Task 5: EvalReportService + Controller
- EvalReportService: 任务完成时汇总(avg 各指标, gatePass = avg 全达标), 写 ai_eval_task.metrics/gate_pass/fail_cases(未达标 caseId+指标)
- EvalTaskController: POST /eval/task/run {caseIds?|kbId?, model?} → 创建任务(异步跑)+ 返回 taskId;GET /eval/task/page(状态/摘要/gatePass);GET /eval/task/get?id=;GET /eval/task/result-page?taskId=(逐题)
- 权限: eval:task:run/query
- 编译 + 启动冒烟(建 3 条题跑任务 → DONE + 指标 + gatePass)

### Task 6: 闸门 + 反馈闭环
- eval-api: `EvalApi.checkGate(kbId) → CommonResult<Boolean>`(最近一次该 kb 任务 gatePass; 无记录 → false + 提示先评测);EvalApiImpl 委托
- knowledge publish 门禁 4: 调 evalApi.checkGate(doc.getKbId()) → false 抛 VERSION_GATE_BLOCKED("评测闸门未通过, 禁止发布");开关 yudao.eval.gate.enabled=false 时跳过(生产默认开; 测试环境可关)
  - ⚠️ 注意: 与发布幂等修复共存——幂等分支(已 PUBLISHED 重跑索引)不查闸门, 仅首次发布查
- chat 反馈闭环: ai_feedback 落库后(chat 侧 FeedbackService 或 Controller)调 evalApi.createCaseFromFeedback(...) 异步生成考题
- 编译 + 冒烟(闸门阻断/放行; 反馈生成考题)

### Task 7: 前端评测页 + 端到端验证
- api/ai/eval/index.ts: case CRUD + task run/page/get/result-page
- views/ai/eval/ 页(或菜单下): 考题集 Tab(表格 CRUD + 批量导入 JSON)+ 评测任务 Tab(发起+列表+详情含逐题结果/失败原因)
