# 对话工作台实施计划(7 任务: 接线/会话消息/管线/转人工/接口/前端/验证)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** chat-server(48083)落地对话工作台:消息 → 复用证据平台判定 → 可作答带引用回答 / 不可作答自动转人工(带上下文摘要)+ 完整前端工作台(会话列表/消息流/AI建议+证据面板/一键采纳/转人工接管/会话记录),WEB 真实链路 + ChannelAdapter 渠道抽象,非流式。

**Architecture:** chat-server 编排;Feign 调 evidence.evaluate(复用完整判定管线)、model.chat(辅助);ai_conversation/ai_message 落库;TransferHandler 五类触发 + 交接摘要;前端改造 workbench-vben 接真实 API。

- 编译 + 启动验证(health + send 骨架仍可跑)

### Task 2: ConversationService + MessageService
- ConversationService: 创建会话(WEB 渠道, customerId 默认 "anonymous")/更新状态(状态机 ACTIVE→TRANSFERRED→CLOSED, take-over 后 TRANSFERRED→HANDLED?——沿用已有 status 枚举 ACTIVE/TRANSFERRED/CLOSED, 接管后置 CLOSED 加 operatorId 记录, 或加 HANDLED 枚举——选: 加 HANDLED 更清晰, 同步改 ai_conversation.status 注释)/分页查询(状态筛选/排序)/更新 intent
- MessageService: 落库 USER/AI/SYSTEM 消息(含 citations JSON/intent/entities/confidence/traceId)/查询会话消息列表(按 create_time)
- DO/Mapper: AiConversationDO/AiConversationMapper/AiMessageDO/AiMessageMapper(照 evidence-server dal 模式, TenantBaseDO + BaseMapperX)
- 注意: conversationId 为空建会话返回新 id;消息必带 conversation_id

### Task 3: ChatPipeline + EvidenceRpcAdapter
- EvidenceRpcAdapter: 包装 evidenceApi.evaluate, 从 SecurityFrameworkUtils.getLoginUser() 取 tenantId/userId(坐席/客户场景;WEB 匿名客户 → 取登录用户或 tenant 上下文, 与检索页一致), 失败降级: RPC 异常 → 返回 answerable=false + reason"评估服务暂不可用"(不抛出)
- ChatPipeline.send(conversationId, message, channel, customerId): 建/续会话 → 落 USER 消息 → 调 evaluate(topK=8, kbIds 空=全部可见——注意: 需先查可见知识库?证据平台内部已做权限, kbIds 传 null 走全部)→ 判定:
  - answerable && answer!=null && !claimFail → 落 AI 消息(含 citations=[evidence[].chunkId] 被 claims 引用的那些, 简化: 取 claims 引用的 evidenceIndex 对应 chunkId)+ 返回 reply
  - 否则 → 交给 TransferHandler(见 T4)
- 会话 intent 更新(取 evaluate 返回?evidence DTO 无 intent——用 model.chat 辅助分析?简化: 转人工关键词判断用规则, intent 落库用 evidence 的 questionProducts/或留空, T4 细化)

### Task 4: TransferHandler
- 触发规则(结构化, 可配置):
  1. answerable=false 且 refusalReason 含"证据不足/未检索/冲突/产品不匹配/阻断"(映射: 冲突→"证据冲突", 产品不匹配→"产品不匹配", 其他→"证据不足")
  2. claimFail=true → "Claim验证失败"
  3. 客户消息含配置关键词(人工/客服/投诉/赔偿/转人工)→ "客户要求"
  4. 情绪词表(太差/垃圾/滚/投诉/赔偿/起诉)→ "情绪激烈"(与 3 可重叠, 优先级 4>3)
- 执行: 会话置 TRANSFERRED + transferReason;组装 summary(原问题 + AI建议[answer 若非空附前 100 字] + 证据摘要[最多 3 条 documentName:versionNo] + 原因);落 SYSTEM 消息(内容=summary, 或单独字段);返回 transferRequired=true
- 手动: ConversationService.transfer(conversationId, reason)/takeOver(conversationId, operatorId)——controller 调, T5 接
- 留痕(BR-022): 采纳/驳回/接管 → ai_feedback 表(有表)或 ai_message SYSTEM 记录——T6 前端配合, 本任务先落接管/转人工的 SYSTEM 消息
