# PRD 对账与缺口清单(2026-08-20)

> 依据: `docs/3-PRD产品需求文档.md`(M1~M8 / BR-001~BR-022) + 实测交付状态
> 结论: M1~M4 基本交付; M5 部分(对话工作台已交付, 多渠道/客户画像未做); **M6/M7/M8 为主要缺口, 优先实现**

## 一、已交付(有实测背书)

- **M1 知识平台**: 文档上传异步化(Kafka)/五策略切分(Semantic/ParentChild/Table/FAQ/Policy)/向量化三写(MySQL+Milvus+ES)/Chunk 管理(编辑/禁用/级联删除)
- **M2 知识治理**: 版本状态机(5 态)/条目级分级审核(必审 POLICY/PRICE/LEGAL, 价格一人审核[用户决定去掉双人复核])/冲突检测与裁决/知识库权限边界(可见角色+有效期)/发布幂等+旧版 EXPIRED
- **M3 检索平台**: 语义理解/改写/拆解(动态意图)/BM25+向量双通道/RRF 融合/BGE 重排/权限前置+越权 0 容忍/品牌一致性门禁
- **M4 证据平台**: 证据组装/去重/冲突/充分性(配置化权重)/生成+Claim 逐句验证(重试≤2)/落库
- **M5 对话工作台(部分)**: ChatPipeline(判定→回答或转人工)/状态机/转人工+交接摘要/多轮上下文/对话工作台前端
- **超越 PRD 的新能力**: 槽位检测(条件抽取+反问)/槽位自动生成(LLM 总结)/入库后一键评测/知识库级动态意图/OUT_OF_SCOPE 短路

## 三、PRD 之外生产级缺口(另行规划)
- 评测体系升级(语义 LLM-as-judge/基准集管理/回归 CI/漂移告警)
- 双回答者收敛(检索 vs 证据)
- ClaimVerifier 放宽/置信度虚高修复
- 表格文档切分检索优化
- 模型按任务配置/提示词模板化/阈值租户级
- 成本/缓存/熔断/prompt injection 防护/自动化测试

## 四、实现顺序(M6→M7→M8)
1. **M6 模型网关**(路由/降级/重试/Token 计量——M8 成本管理的地基)+ **Prompt 管理**(DB 版本化)
2. **M7 规则引擎(Drools: DRL 存 DB 按租户/场景, 运行期编译, 规则优先于 LLM)+ 工具注册表 + 工作流(复用 flowable)
3. **M8 审计日志 + 链路全快照 + 成本管理 + ABAC + 多租户治理**
